# LEANODM 产品概览页设计规格

日期：2026-09-28

页面：`/products/`

状态：设计审核稿。仅提交本页及关联的夜灯展示层级修订；用户审核本页后才进入下一个页面。全站设计阶段尚未结束，不进入具体文案、实施计划或代码阶段。

设计依据：[已批准架构及夜灯例外修订](2026-09-28-leanodm-site-architecture-design.md)、[已批准首页及夜灯例外修订](2026-09-28-leanodm-home-design.md)。

本规格中的模块名称、字段和组件名称用于设计讨论，不是最终网站文案。第 5 项按用户要求提供一个建议 H1；不撰写副标题、正文、SEO 元描述或新的按钮营销文案。

## 页面设计结论与架构一致性

推荐把本页设计为产品领域导览与项目适配入口。重点是让采购商找到匹配领域，并知道有现款、样品、概念或成熟设计时分别从哪里开始。

| 考虑的方向 | 取舍 |
| --- | --- |
| 三个重点品类＋补充应用＋简短项目适配（推荐） | 保持主要业务清晰，同时保留跨品类订单入口和四个已有品类地址 |
| 四个同权品类卡片 | 导览简单，但仍容易让夜灯被理解为核心业务，不符合本次纠正 |
| 全型号目录与大量筛选 | 适合按明确型号采购的任务，会把本页重心转为找现款；当前页面阶段不采用 |

本轮夜灯处理规则：

- 四个初始品类地址全部保留，页面数量不等于展示权重。
- 玩具与收藏品、文创礼品、文具使用主要卡片；夜灯进入较低权重的补充应用模块。
- Products 下拉同步区分主要品类与补充应用，不能仍把四类放成同权大图菜单。
- 首页不使用夜灯主图、并列核心卡片、专属主案例或百万套统计。
- 夜灯保留普通可访问的品类链接与未来独立案例；本页不展开照明产品线，不创建泛化的 Other Products SEO 页面。
- 不把普通塑胶产品全部描述为含电子功能，也不将电子功能设为项目准入条件。

## 1. 搜索意图

主要是商业调研与产品范围确认：买家需要判断 LEANODM 可以开发制造哪些产品、是否覆盖自己的项目，以及应进入哪个品类或服务页面。

包括三种到访情境：

1. 从首页或导航进入，快速寻找对应产品领域。
2. 从搜索进入，希望了解企业的产品范围并进一步筛选。
3. 已有设计或概念，尚不能把产品归入现有分类，希望直接找到项目评估入口。

本页解决产品匹配问题。工厂整体可信度由首页与 About 深入介绍；具体产品规格、采购问题和长尾搜索由品类及详情页承接。

## 2. 目标买家

- 首要：玩具、文创礼品和文具品牌的采购经理、产品经理及产品开发负责人。
- 同时服务：寻找其他塑胶或电子产品 OEM/ODM 供应商的品牌与采购团队。
- 辅助审查者：需要判断材料、结构、电子与制造适配性的工程或供应商质量人员。

页面同时允许两种采购起点：选择已有产品方向继续定制，或携带自己的产品设计与要求进入评估。不能要求买家先找到一个现有型号才能联系。

## 3. 主要 SEO 关键词／主题

主要主题：**LEANODM 可提供 OEM/ODM 制造的塑胶与电子产品范围及分类**。

候选词组方向为 OEM/ODM product range、custom plastic and electronic products、LEANODM products。它们用于定义内容主题，不作为已验证的搜索量、排名或流量目标。

| 页面 | 回答的问题／主题归属 |
| --- | --- |
| 首页 | 企业是谁、综合定位是什么、为什么值得进一步了解 |
| `/products/` | 有哪些产品领域，我的项目应进入哪个页面 |
| `/products/toys/` | 玩具与收藏品的具体制造和开发需求 |
| `/products/gifts/` | 文创礼品与品牌商品的具体制造和开发需求 |
| `/products/stationery/` | 文具的具体制造和开发需求 |
| `/products/night-lights/` | 夜灯的具体制造需求；保持补充应用地位 |
| `/customization/` | 各类项目起点如何与工厂开展合作 |

本页不需要把每个品类关键词反复写进 H1 与正文，也不将产品总览包装为覆盖所有高流量词的单一落地页。它的主要 SEO 价值在于明确的产品范围、可发现的品类链接与完整的主题关系。

面向 AI 搜索的内容要求与买家阅读一致：类别名称、典型范围、可承担工作与关联证据以正文表达；原始产品照片提供辅助；不能只有图片上的文字或需要操作筛选才能出现的内容。Google 的指南强调可靠的实际经验内容、清晰技术结构与可发现的链接，本规格据此组织内容，不增加特殊 AI 文本文件任务。

## 4. 页面目标

第一目标：帮助买家进入匹配的品类页面。

第二目标：让已有设计、尚未归类或需要开发的项目进入适合的服务页或 Contact。

第三目标：提供足够的制造与管理佐证，支持继续了解，而不是让买家在总览页完成整套工厂审查。

未来观测指标为：品类入口点击、对应服务页访问、来自本页的有效项目提交，以及夜灯与三个重点领域的访问分布。夜灯点击率不是本页需要最大化的目标；表单开始、CTA 点击与实际收到的有效询盘分开计量。此处不设置没有基线的数值目标，也不实现埋点。

## 5. 建议 H1 标题

**Product Categories for OEM & ODM Manufacturing**

这是用于审核页面职责的标题建议，不是完整文案交付。它明确本页是制造业务的产品领域总览；三个重点领域由紧随其后的类别标题与图片表达，塑胶及电子能力通过简短范围说明表达。

首屏内容规格：面包屑 Home → Products、H1、简短范围说明、进入主要品类区的浏览动作，以及复用全站项目咨询入口。不使用大幅灯具图、夜灯销售数字或占用大量高度的工厂宣传 Hero。

## 6. 版块顺序

1. 紧凑的产品范围说明与浏览入口。
2. 三个重点产品领域。
3. 其他塑胶电子应用与项目入口，夜灯作为补充链接。
4. 按项目起点选择合作方式。
5. 支撑产品交付的制造、精益与质量佐证。
6. 下一步行动与项目咨询。

本页不重复首页完整的公司介绍、阶段流程、数据统计、长篇客户案例和通用 FAQ。正文按产品判断任务组织；如确有本页独有的采购问题，可在对应模块直接回答，不为凑模块追加 FAQ 区。

## 7. 所需内容

| 模块 | 必需内容字段 | 信息量与呈现边界 |
| --- | --- | --- |
| 产品范围说明 | 本页提供什么、重点领域、其他塑胶电子项目可评估、OEM/ODM 属性 | 短说明即可，不撰写品牌宣言或重复工厂故事 |
| 三个重点领域 | 品类名称、代表产品图、典型产品范围、可承担工作的简要范围、品类链接 | 每类使用相同字段和同等视觉权重；每类图片可展示 2–3 个代表实例。具体型号、参数和详细定制选项留给下一级 |
| 其他应用 | 可评估其他产品的材料/结构/电子功能需求；夜灯品类普通链接；合作评估与 Contact 入口 | 不使用与三张重点卡片等大的夜灯卡片；不展示大图、百万套数字或 Amazon 标签；不暗示完整照明产品线 |
| 合作方式 | 当前项目起点、对应服务、买家需准备的信息类型、下一页 | 使用下面的紧凑对应表，代替完整开发流程或又一组大型营销卡片 |
| 交付佐证 | 实际产品与承担工作的对应、可公开的过程实例、质量/精益实践摘要、相应专题链接 | 采用 2–3 个短证据单元；主图与示例优先来自重点领域。解释这些能力如何支持产品要求，不罗列全部设备 |
| 下一步 | 继续浏览或提交自己项目的选择、进入 Contact 后需准备的信息概览 | 保持已批准的全站咨询入口，不在此加入完整 RFQ 表单 |

合作起点的逻辑对应如下。表内为设计描述，不是最终页面文案：

| 买家当前已有的内容 | 对应服务 | 目标页面 |
| --- | --- | --- |
| 可供定制的现有产品方向，主要调整品牌、外观或包装 | 现款定制 | `/customization/existing-products/` |
| 参考产品、样品或现有设计，需要结构/功能调整 | 产品改款 | `/customization/product-adaptation/` |
| 产品概念与功能目标，需要形成可制造设计 | 新产品开发 | `/customization/new-product-development/` |
| 成熟设计及生产要求，需要生产导入与制造 | OEM 制造 | `/customization/oem-manufacturing/` |

卡片上展示的客户项目与可供定制现款应标明不同性质；不能让买家把项目照片误认为可直接购买的现货 SKU。具体 MOQ、价格、交期与参数在对应页按实际条件说明，本页不设置跨品类的统一数值。

## 8. 所需证据／佐证

用户已确认资料充分；下表用于安排资料位置，不要求先提交资料才能继续设计。

| 所需资料 | 支持的判断 | 使用方式 |
| --- | --- | --- |
| 玩具、文创礼品、文具的实际产品照片与基本信息 | 产品范围与真实经验 | 构成三张重点卡片，附可读取的文字说明 |
| 代表产品对应的厂内开发/生产工作资料 | 工厂实际承担哪些工作 | 在交付佐证中呈现产品与工作之间的关系 |
| 精益现场或标准作业实例 | 管理方法怎样支持一致性与过程稳定 | 简短说明并链接精益中心，不推导未经定义的改善百分比 |
| 对应产品的检验或测试资料样例 | 如何判断产品是否达到要求 | 说明检验/测试对象与用途，链接质量专题 |
| 已批准可公开的脱敏案例 | 是否有类似项目交付经验 | 用摘要链接唯一案例页，不在总览复制完整故事 |

夜灯链接本身无需通过大型案例与产量数字增强权重。电子夜灯案例继续留在既定第 7 阶段设计。工厂资料沿用东莞 Xinyinhai 主体，不能把项目产量改写为全厂规模。

## 9. CTA 策略

- 浏览型买家：品类卡片的主要动作是进入相应品类页。
- 已有产品需求的买家：复用已批准的全站 **Discuss Your Project** 入口到 `/contact/`，无需先挑选现款。
- 其他应用模块：提供项目评估入口与较低权重的夜灯品类链接，二者目标清楚分开。
- 合作方式模块：各起点进入对应服务页；不确定路径的用户可进入 `/customization/` 或直接联系。
- 页面结尾保留一个主要项目咨询动作；不在每个证据单元重复设置同等级询盘按钮。
- 来源页、所选类别和项目阶段可作为后续 Contact 的上下文；表单将由 Contact 规格定义，本页不新增表单或提交逻辑。

除既有全站 CTA 外，本轮仅规定动作与目的地，其他按钮用语在文案阶段确定。

## 10. 内部链接策略

| 来源 | 目标 | 目的 |
| --- | --- | --- |
| 三个重点卡片 | `/products/toys/`、`/products/gifts/`、`/products/stationery/` | 建立清晰的主要产品路径 |
| 补充应用模块 | `/products/night-lights/` | 保留第四品类的可发现性并控制展示权重 |
| 未列出的产品项目入口 | `/customization/`、`/contact/` | 支持跨品类项目，不新建泛化分类页 |
| 合作起点对应表 | 四条既有服务路径 | 根据项目成熟度分流 |
| 交付佐证 | 与证据直接相关的 `/manufacturing/`、`/quality/`、`/lean-manufacturing/` 页面 | 支持更深入的制造与管理判断 |
| 案例摘要 | 对应唯一案例页或 `/case-studies/` | 查看真实工作和结果 |
| 面包屑及返回入口 | `/`；各品类页面返回 `/products/` | 保持父子关系与浏览连续性 |

本页使用可以直接访问的普通链接，夜灯入口不隐藏在搜索结果、筛选状态或仅悬停可见区域中。Google 的网站结构指南支持通过类别和产品之间的链接发现内容；降低视觉权重不需要删除路由或阻止索引。

品类页链接自己的产品详情；本页不需要直接罗列全部型号。跨分类展示的同一产品沿用唯一详情地址，不能为同一实物复制多个页面。补充应用只是本页模块，不新增独立 URL 或筛选参数页面。

| SupplementaryApplications | 本轮提出的组件模式，尚未实现 | 为跨品类项目与夜灯普通链接提供独立低权重位置 |

组件输入至少包括名称、范围说明、图像与替代文字、目标链接；品类另有明确的展示分组属性。分组控制信息层级，不能靠把夜灯排在第四位来模拟低权重。

本页仅有少量领域入口，首版无需站内搜索、全型号筛选、轮播或无限加载。导航与核心信息不依赖动画才能显示。无目标内容的卡片不发布，不能出现空链接或假下载。

## 12. 移动端适配考量

- 顶部保持紧凑，让用户尽早看到产品领域；不以固定全屏 Hero 延迟浏览。
- 三个重点卡片在窄屏按单列显示，顺序保持玩具、文创礼品、文具；卡片中的典型范围保持可扫读。
- 补充应用放在三个重点领域之后，保留清楚标题与文字链接；夜灯不变成同等大小的第四张卡片，也不在手机上消失。
- 类别与正文采用正常文字，不把说明写死在图片中；图片保留合理比例，不裁切产品关键结构。
- 合作起点表在窄屏转为有标签的条目，每条保留起点、服务和入口，不要求横向拖动阅读。
- 主要卡片保留一个明确主链接，相关动作分开；避免嵌套点击区或只能悬停操作。
- 复用全站菜单的展开、当前状态、焦点返回和键盘规则；触控目标按至少 44×44 CSS px 设计。
- 关键分类和项目链接在脚本延迟或失败时仍可使用；遵循减少动画偏好，不新增覆盖正文的固定咨询浮层。
- 后续实施验收覆盖 360px、390px、768px 以及桌面导航切换附近宽度，检查横向溢出、图片裁切、阅读顺序与触控操作。本轮不进行页面实现或运行这些界面测试。

## 审核标准与下一步

本页可用以下问题审核：

1. 主要业务是否一眼明确为玩具、文创礼品和文具？
2. 其他塑胶电子项目是否仍有容易找到的合作入口？
3. 夜灯是否保留品类地址与可发现链接，同时避免核心业务印象？
4. 已有成熟设计的 OEM 买家是否能直接找到路径？
5. 页面是否以产品判断为主，精益与质量作为相关佐证？
6. 当前范围是否只包含设计规格，而没有进入具体文案或代码？

本文件提交审核后停止推进新页面。收到本页批准后，按既定顺序进入第一个产品类别页面的设计；不会把批准自动解释为编写产品文案、实施计划或生产代码。
